## Supported append boundary

`legacyReconciliationService.append` requires independent protected evidence
verification in addition to its separate native decision signature. It locks the
scheduler and complete native hold inventory under the existing advisory lock;
checks current epoch/drain, exact original lease/run/hold/scopes and native
inactivity; passes the entire inventory and its sorted source/hold-fingerprint
hash to the mandatory host verifier; and requires an exact decision/inventory
hash and shortest evidence expiry return before the append-only CAS insert.
After the verifier returns, native append rechecks that the safe-integer expiry
is still future, within sixty seconds, and no later than decision expiry. The
Python bridge returns the minimum inventory/artifact/operator/decision deadline.
An append cannot use a still-valid decision to extend expired evidence. Freshness
is checked at append; accepted immutable reconciliation facts persist until
explicit revocation or epoch/binding change, rather than expiring on a timer.
Missing verification, mismatched inventory and unavailable evidence leave the transaction unchanged. It schedules
the supported lifecycle coordinator after commit. No HTTP route is installed.

The verifier is an integration contract, not proof merely because a callback
exists. A production implementation must authenticate independent route,
retirement, stop, workspace, session, credential and operator evidence; verify
current authority/incarnation and durable history; and bind the complete current
inventory. Test callbacks are explicitly synthetic and must not be deployed.
The offline Python reviewer additionally supports a distinct protected inventory
root, a 60-second snapshot freshness window and the exact native inventory hash.
Its conservative inventory path requires evidence for **every** authoritative
hold. A future shared-scope-only optimization needs a separately verified complete
scope closure; callers cannot filter away A or environment-only occupancy.

## Ordered use and prospective inspection component — 2026-10-20 continuation

`protected-execution/production/decision_use.py` now supplies a disconnected,
default-refusing interface for exact authority-owned admission/lifecycle effects,
ordered revocation, and uncertain-effect inspection. An operation binds the full
original closure and accepted references, a unique effect ID, exact native
transaction hash, purpose, challenge and pinned authority/history incarnations.
The authority contract consumes the ID durably before execution, serializes every
effect against deny intent, and retains unfinished pre-deny work until settled.
A completion response describes a past effect; it cannot authorize a subsequent
native write. A transport exception leaves completion uncertain and requires
inspection by the original request hash and effect ID without execution replay.

`decision_history.py` adds exact prospective-intent request construction and
signature-only inspection. The intent binds original hold, action, next sequence,
previous hash, exact decision hash, complete inventory hash and operator approval
hash. Prospective, unknown, missing and uncertain outcomes remain held. Only an
exact committed inspection produces an observation, never an append/use permit.
Verification uses a protected public-key handle; no private signing key, readable
MAC secret, issuer, rotation service or custody installer is introduced.

These are component interfaces and synthetic protocol checks. The native
`legacyHoldIsReconciled` and `legacyLeaseIsReconciled` remain unchanged and cannot
use these observations as authorization. Actual integration must replace every
accepted-decision use with an authority-owned effect ordered through the native
transaction commit. Holding a local lock or verifying a signed receipt before a
later DB write leaves a revocation gap. A reviewed distributed commit/current
native transaction protocol, mandatory call-site coverage, durable external
history/high-water continuity, protected issuers, independent custody and
cancellable workers remain absent. No real append, revocation, hold clearance,
new receipt or operational acceptance occurred; both A/original shared families,
